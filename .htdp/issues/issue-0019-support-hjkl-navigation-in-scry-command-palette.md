## Migrated OUS content

## Summary

Scry should support Vim-style hjkl navigation for browsing command-palette results after Escape moves focus from query entry into result/navigation mode.

## Details

## Parent issue

Reported during QA session

## What's wrong

Scry's command palette does not support hjkl navigation for browsing results. Because the search input is focused by default, pressing h, j, k, or l currently edits the query instead of moving through results. After the user presses Escape into result/navigation mode, these keys should navigate rather than edit text.

## What I expected

After Escape moves focus out of the search input, h/j/k/l should work as command-palette navigation keys for browsing history results. Search text entry should still behave normally while the search input is focused.

## Steps to reproduce

1. Load Scry as an unpacked Chrome extension in Google Chrome 147 on macOS.
2. Open the Scry command palette and run a search with multiple history results.
3. Press Escape to move from search input into result/navigation mode.
4. Press h, j, k, and l.
5. Observe whether Scry provides Vim-style result navigation without changing the query.

## Blocked by

- #0015 (.ous/issues/0015-define-scry-command-palette-focus-lifecycle-with-escape.md)

## Additional context

The core need is keyboard-first result browsing without sending navigation characters into the query. If result pagination is added in #0014, h/l can be considered for previous/next page while j/k handle result selection.

- [x] Enter opens the selected result from result/navigation mode.
- [x] h/j/k/l do not hijack normal text entry while the search input is focused.
