## Migrated OUS content

## Summary

Scry's open shortcut should open a focused command palette search box. Chrome's side-panel focus model prevents the original side-panel version from focusing search reliably, so Scry is moving the Command+K flow to the extension action popup.

## Details

## Parent issue

#0002 (.ous/issues/0002-bootstrap-mv3-side-panel-shell-with-cmd-ctrl-k-toggle.md)

## What's wrong

When Scry is loaded, Command+K is expected to open Scry and focus the search box so the user can type immediately. Chrome opens the side panel but does not transfer focus into it. The popup command palette should provide the same recall UI with reliable autofocus.

## What I expected

Command+K opens Scry as an extension popup command palette on the user's Chrome 147 Mac install, with focus in the search box.

## Steps to reproduce

1. Load Scry as an unpacked Chrome extension in Google Chrome 147 on macOS.
2. Visit a normal web page or New Tab.
3. Confirm Scry's action shortcut is assigned to Command+K in Chrome's extension shortcut settings.
4. Press Command+K.
5. Observe whether the Scry popup opens with focus in the search box.

## Blocked by

None — can start immediately.

## Additional context

The reported environment is Google Chrome 147.0.7727.101 on macOS arm64 for a personal extension. Web research found Chrome's Side Panel surface does not reliably receive focus when opened from a shortcut, and there is no extension API to force focus from the page into the side panel. Chrome action popups do receive focus, so the user chose to switch Command+K to a popup command palette.
