## Summary

Scry's command-palette contents should fit within the visible popup height; result browsing should use pagination to reach additional matches.

## Details

## Parent issue

Reported during QA session

## What's wrong

When Scry shows enough history results, the side-panel contents extend past the screen and the panel gets a vertical scrollbar. This makes the search UI feel like an overflowing page rather than a bounded recall panel.

## What I expected

The command palette should fit the visible popup. Search results should be shown in a bounded page, with pagination or equivalent page controls to reach all available matches without making the whole popup overflow.

## Steps to reproduce

1. Load Scry as an unpacked Chrome extension in Google Chrome 147 on macOS.
2. Open the Scry command palette.
3. Search for a query that returns more history results than fit in the visible panel height.
4. Observe whether the command-palette contents stay bounded and expose pagination instead of whole-popup scrolling.

## Blocked by

None — can start immediately.

## Additional context

Scry is a history-first URL recall command palette. The desired browsing model is a fixed-height popup experience where the search input, status, result page, and controls remain usable while paging through matches.

## Acceptance Criteria

- [x] The command palette fits within the visible Chrome popup height without whole-popup vertical overflow for a normal result page.
- [x] Users can reach additional matching history results through pagination or equivalent page controls.
- [x] Search input, status, and footer/navigation controls remain visible and usable while moving between result pages.
