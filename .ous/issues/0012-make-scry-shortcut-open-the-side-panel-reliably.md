## Summary

Pressing Scry's advertised keyboard shortcut does not open the Scry side panel, leaving no reliable keyboard path into URL recall.

## Details

## Parent issue

#0002 (.ous/issues/0002-bootstrap-mv3-side-panel-shell-with-cmd-ctrl-k-toggle.md)

## What's wrong

When Scry is loaded, Ctrl+K / Command+K is expected to open the Scry side panel, but the shortcut does not open it. Chrome's MV3 docs allow opening an extension side panel from a keyboard shortcut, so this should either work or clearly guide the user when Chrome cannot assign the advertised shortcut.

## What I expected

The assigned Scry shortcut opens the side panel and focuses the recall search. If Chrome cannot assign the advertised shortcut because of a browser, operating-system, or extension conflict, Scry should make the remap requirement visible to the user.

## Steps to reproduce

1. Load Scry as an unpacked Chrome extension.
2. Visit a normal web page or New Tab.
3. Confirm Scry's "Toggle Scry" shortcut is assigned in Chrome's extension shortcut settings.
4. Press Ctrl+K on Windows/Linux or Command+K on macOS.
5. Observe whether the Scry side panel opens and the recall search receives focus.

## Blocked by

None — can start immediately.

## Additional context

The reported environment is Google Chrome 147.0.7727.101 on macOS arm64 for a personal extension, so Chrome supports opening an extension side panel from a keyboard shortcut. Chrome Commands docs still say extension shortcuts can be left unassigned when they conflict, and some Chrome or operating-system shortcuts take priority and cannot be overridden. The product behavior and setup guidance need to match those constraints on the user's machine.

## Acceptance Criteria

- [ ] The assigned Scry shortcut opens the side panel from a normal page.
- [ ] The assigned Scry shortcut opens the side panel from New Tab.
- [ ] If the advertised shortcut is unavailable, the user gets clear guidance to assign or remap it in Chrome's extension shortcut settings.
