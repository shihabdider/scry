## Summary

Scry needs a keyboard shortcut to return from result/navigation mode back to the search input without closing and reopening the command palette.

## Details

## Parent issue

Reported during QA session

## What's wrong

After pressing Escape to leave search entry and browse results, there is no direct keyboard path back to editing the query. The user has to close and reopen Scry or use the mouse.

## What I expected

When Scry is in result/navigation mode, pressing `i` should focus the search input so the user can edit the query immediately. Normal text entry should remain unchanged while the search input is already focused.

## Steps to reproduce

1. Load Scry as an unpacked Chrome extension in Google Chrome 147 on macOS.
2. Open Scry with Command+K.
3. Type a query.
4. Press Escape to move into result/navigation mode.
5. Press `i`.
6. Observe whether focus returns to the search input without closing the command palette.

## Additional context

This follows the Vim-style mode model already used by Scry: Escape leaves insert/search mode, hjkl navigates results, and `i` should re-enter insert/search mode.

## Acceptance Criteria

- [ ] Pressing `i` in result/navigation mode focuses the search input.
- [ ] The current query text is preserved when returning to search input.
- [ ] Pressing `i` while the search input is focused inserts text normally.
- [ ] The footer hint mentions `i` as the way back to search.
