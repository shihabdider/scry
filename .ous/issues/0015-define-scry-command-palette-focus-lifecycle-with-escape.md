## Summary

Scry needs a predictable focus lifecycle: open into search, Escape into result navigation, and Escape again out of the command palette.

## Details

## Parent issue

Reported during QA session

## What's wrong

Focus in and out of Scry feels janky. Scry starts in the search box, but there is no clear mode transition from query entry to result navigation, no second Escape behavior to leave, and no reliable way for the open shortcut to start in search.

## What I expected

Scry should support this flow: open shortcut → focus in search box → input query → Escape focuses result/navigation mode → Escape again closes or leaves the command palette.

## Steps to reproduce

1. Load Scry as an unpacked Chrome extension in Google Chrome 147 on macOS.
2. Open the Scry command palette with Command+K.
3. Type a query in the search input.
4. Press Escape and observe whether focus moves to result/navigation mode.
5. Press Escape again and observe whether the command palette closes or leaves focus.
6. Press Command+K again and observe whether Scry opens with focus in the search input.

## Blocked by

None — can start immediately.

## Additional context

This focus-mode boundary is needed before Vim-style result navigation can work without corrupting the search query. Result activation should close the command palette after opening the selected page.

## Acceptance Criteria

- [x] Opening or refocusing Scry places focus in the search input.
- [x] Pressing Escape while the search input is focused moves to result/navigation mode without closing the command palette.
- [x] Pressing Escape again from result/navigation mode closes or leaves the command palette.
- [x] Opening a selected result closes the command palette.
- [x] Command+K opens with focus in the search input.
- [x] Search typing remains unchanged while the search input is focused.
